# Focused regression RED → GREEN
Use for approved behavior changes and bugs. Read real test conventions/package scripts and actual runtime source. Author a minimal test using real production runtime, deterministic time source, valid inputs, exact target; no mocking result to force failure. Save test-only candidate in existing authorized work branch using safe-delivery, verify compare/readback. M2a means test artifact only, not RED. Never modify production code before intended failure is observed.
M2b: execute the focused test on the baseline production source plus new test (existing permitted local/CI runner only). Record command, exact SHA, logs/exit status and expected vs actual assertion. Setup/import/network failure is NOT RED. If no runnable environment, record blocker; use existing permitted test route if present, not new workflow or paid service. Keep test-only commit explicitly incomplete.
M2c: smallest approved production fix; verify test unchanged except justified fixture correction. Run same test; verify pass, then affected existing regression/harness. Keep observed failures in report; max 2 fixes for same root cause. No skipping assertion, loosening thresholds, changing gauge or timeline. Full integration suite required at integration gate, not every intermediate run. No merge based on RED or a candidate.
