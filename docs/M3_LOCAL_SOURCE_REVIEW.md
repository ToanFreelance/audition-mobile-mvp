# M3 source review import — Cheering / Arm Stretching (QA only)

Owner supplied two binary Mixamo FBX files. Offline parsing with the existing source-retarget algorithm (FBX PreRotation, local animation rotation, PostRotation inverse, full source hierarchy at 30fps) found 65 animated source models each. Cheering: 88 frames, 2.9s. Arm Stretching: 267 frames, 8.8667s. Native source ankle displacement from first pose is <= 0.51cm and <= 0.31cm respectively; Arm Stretching's right toe is up to 2.04cm. These measurements are source-only, not proof of native M3 contact.

The original FBX bytes and extracted source package are kept out of the repository. The owner receives a local JSON review package with all source world-space delta quaternion samples (int16, +/-32767), normalized hip offsets and source SHA-256. This package is not an independent public asset distribution. The GitHub connector cannot consume the sandbox's binary files directly.

The isolated single-actor /tools/lobby-qa-sketch?mixamo=1&clipReview=1 demo accepts that package through a local file control. Data is parsed and validated in browser only; no upload to the server. Cache in sessionStorage allows the same package on the male/female views. The existing M3 native rest is captured before any idle action. For each frame, source world rotation delta * native target world rest rotation, then animated parent inverse, generates native target local quaternion tracks. Root offsets scaled by target rest hip-to-foot distance are written to hips only. New actions bind to actor bone UUIDs and use the existing AnimationMixer. No runtime IK, no V7/V8 postprocessing on these new source-retarget clips, no actor remount, and no random inclusion. Old 9/8 catalog remains unchanged (11/10 only after local import). No change to Dwarf exclusions, actual Waiting Room, room state, network or gameplay.

Tests: existing clip review plus a synthetic 31-frame identity-delta package for control parsing/playback, same mixer, next and cross-rig session cache. Synthetic test proves UI/runtime import path only, not exact appearance of owner FBX. Owner should inspect delivered package on both native M3 rigs before adding either to random. Do not merge.
